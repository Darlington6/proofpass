How another company would integrate this

This page proves the pattern works. Adopting it for a real product means doing these four things — it's a real, bounded engineering task, not a plug-in.

  1. Decide the policy

    What threshold (or range) to require, and what private fact it's checked against — age here, but the same shape fits income, credentials, or membership.

  2. Deploy their own contract

    The same Compact contract, deployed to a real Midnight network with their own threshold baked in — not a shared instance with other companies.

  3. Swap the frontend step

    Replace the raw data field with a proving step, using Midnight's wallet connector so the proof is generated on the applicant's own device.

  4. Swap the backend check

    Read the on-chain pass/fail result for the applicant's id instead of a stored value in their own database.

Scope, honestly: the age check on this page is one example of the pattern (private witness → circuit logic → disclose only the derived result), not the limit of it. The same shape proves an income threshold, a credential, or membership without writing a fundamentally different contract. What's demoed here is deliberately narrow — a single check, a single-session contract — to keep the core claim easy to verify end-to-end within a hackathon weekend.
